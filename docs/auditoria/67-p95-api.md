# P1-13 — p95 da API: série de produção existe e está estourada (23/11/2026)

> **Correção de estado:** a versão anterior deste doc dizia "sem série" porque
> este worktree não tem credencial de banco de produção. O dono mediu a série
> **read-only na VPS** no mesmo dia: há série, e o alvo está estourado. A tese
> "sem série" estava errada e foi apagada. Os números abaixo são **medidos pelo
> dono em produção**, não estimativa e não número de QA.

## Medição de produção (7 dias)

| Rota | Amostras | p95 |
|---|---:|---:|
| `/api/v1/conversations` | **259** | **2673 ms** |
| `/api/v1/commercial-orders` | 3 | 1378 ms |
| `/api/v1/contacts` | 4 | 1052 ms |
| `/api/v1/invoices` | 1 | 971 ms |
| **Total (rotas quentes)** | **267** | **2660 ms** |

Erros 5xx: **0**. Alvo do SLO: **p95 ≤ 800 ms**. Veredito: **estourado**
(2660 > 800); a pior rota, `/api/v1/conversations`, tem 259 das 267 amostras
(97%) e p95 2673 ms — é nela que está o problema de latência do Inbox.

## Por que o Sentinel não viu (P0-7/P0-8)

`fn_slo_api_resumo` é `returns table(total, erros, p95)`; `supabase.rpc()`
devolve **array de linhas**:

```text
[{ total: 267, erros: 0, p95: 2660 }]
```

Os dois leitores faziam `(data as { total?: number }).total` → `undefined` →
`Number(0)` → `total = 0`:

- `lib/sentinel/coleta.ts`: `sloApi.total = 0` → `slosEstourados()` devolve
  `null` → **nenhuma ocorrência aberta**;
- `app/api/v1/admin/observabilidade/route.ts`: tela mostrava "sem histórico"
  com 267 amostras na tabela.

Correção em PR separado (#810): normalização única em
`lib/observabilidade/linha-rpc.ts` (array **e** objeto), usada pelos dois
leitores. Testes com 267/2660 provam total > 0 no painel e na coleta, e a
abertura de `plataforma.slo_estourado|latencia` com severidade crítica.

## O que ainda não é medido

- p95 **após** o deploy do #810: a próxima varredura deve abrir a ocorrência;
  se não abrir, o bug não foi fechado.
- `EXPLAIN (ANALYZE, BUFFERS)` de `/api/v1/conversations` em produção: a causa
  dos 2673 ms ainda **não foi diagnosticada**. Não propor índice nem mudar
  query antes dessa medição — é item separado, em outro PR.

## Como reproduzir na VPS (somente leitura)

```sql
select count(*) as amostras,
       round(percentile_cont(0.95) within group (order by duration_ms)::numeric, 1) as p95_ms,
       min(created_at), max(created_at), count(distinct route)
from public.api_request_samples
where status between 200 and 399
  and created_at > now() - interval '7 days';
```
